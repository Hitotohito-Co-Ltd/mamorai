# 上番・下番の位置確認（ジオフェンス）

上番連絡・下番連絡を押したときに、スマホの現在地が現場の範囲内かを確認します。
現場ごとに「使わない／記録だけ／範囲内でのみ報告可」を選べます。

## 現場の設定（管理コンソール → 上番報告設定 → 現場を選ぶ）

1. 「上番・下番の位置確認」で使い方を選びます。
   - **使わない**：位置は取りません（既定）。
   - **記録だけ**：位置を記録します。範囲外でも報告でき、一覧で「範囲外」と分かります。まずはこちらで数日試すのがおすすめです。
   - **範囲内でのみ報告可**：範囲外・位置なし・誤差が大きいときは報告できません。
2. 「地点を入力」に、Googleマップで現場を開いたときに住所の下に出る Plus Code をそのまま貼り付け、「読み取る」→「地図で確認」→「この地点にする」。
   - 受け付ける形：`MQH9+JM9 中央区、東京都`（短いコード＋地域名）、`8Q7XMQH9+JM9`（完全なコード）、`35.6790, 139.7692`（緯度・経度）、GoogleマップのURL。
   - 短いコードは地域名の都道府県から場所を復元します。北海道など広い県の端の現場は、完全なコードか緯度・経度で入れてください。
   - 現場にいるなら「この端末の現在地」でも登録できます。
3. 範囲（半径）を選んで保存します。迷ったら 200m。

設定を変えられるのは管理者と、その現場を担当する支店・権限者だけです（本社PC・教育センターは不可。DBでも拒否）。

## 判定の基準

- 現場の中心からの距離が「半径 ＋ 位置の誤差（最大100m）」以内なら範囲内。
- 位置の誤差が 300m を超える場合は判定に使いません（「範囲内でのみ」では報告できません。窓際や屋外で取り直してもらいます）。
- 対象は上番連絡・下番連絡だけです。起床・出発（自宅から送る）とその他の報告は対象外です。
- 判定はスマホの画面（事前の案内）と DB（最終判定）で同じ基準です：`packages/input-core/src/geo/geofence.ts` の `judgeGeofence` と `supabase/migrations/0412_jyoban_geofence.sql` の `jyoban_geo_judge`。

## 勤務員への案内

- 初回の上番で「位置情報の利用を許可しますか」と出たら「許可」を押してもらいます。
- 拒否してしまった場合は、スマホの設定（iPhone：設定 → プライバシーとセキュリティ → 位置情報 → Safari／ホーム画面のアプリ、Android：Chrome のサイト設定 → 位置情報）で許可に戻します。
- 位置は報告を押した瞬間だけ取り、常に追跡はしません。「使わない」現場では位置を保存しません。
- 電波がない場所でも位置は取れます。送信待ちになった報告は、押したときの位置で判定します。

## 注意

- スマホの位置は、位置を偽装するアプリなどで変えられます。位置確認だけでは不正を完全には防げません。顔・指紋の本人確認（生体認証）と組み合わせ、「範囲外」が続く人は現場責任者が確認してください。
- 位置（緯度・経度）は個人情報です。上番報告の記録と同じ期間だけ保管し、目的（上番・下番の確認）以外に使わないでください。就業規則や勤務員への説明文に、位置を確認することを書いておくことをおすすめします。

## 反映の順番

1. Supabase で `0412_jyoban_geofence.sql` を実行（0406〜0409・0411 の後）。
2. 管理コンソールと勤務員アプリを公開。
3. 現場ごとに「記録だけ」で試し、範囲外の記録が出ないことを確認してから「範囲内でのみ報告可」に切り替える。

アプリは 0412 がまだ入っていない DB でも動きます（位置確認は「使わない」扱い）。
