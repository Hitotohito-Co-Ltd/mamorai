# MAMOR-AI UI 仕様書（実装用）

対象リポジトリ：`Hitotohito-Co-Ltd/mamorai`（main, 2026-11-05 時点）
見た目：`screens/<画面>.png` ／ 構造と文言：`html/<画面>.html` ／ 色・寸法：`design-tokens.css`

## 0. 共通ルール

- **色**は `design-tokens.css` の `--mm-*` だけを使う。状態の色は「文字 / 背景 / 枠」をセットで使う（§0.3）。
- **文字**は Noto Sans JP。数値は `font-variant-numeric: tabular-nums`。
- **押せる要素**は高さ 44px 以上（スマホの主ボタンは 52〜60px）。`<button>` `<a>` `<input>`＋`<label>` を使い、div に onClick を付けない。アイコンだけのボタンは `aria-label` を付ける。
- **コントラスト**：文字は 4.5:1 以上。緑 `#10B981` は文字や白文字ボタンの背景に使わない（`--mm-green-text` を使う）。
- 絵文字は使わない。アイコンは線のSVG。
- ロジック（状態判定・集計・並び順・期限計算）は `packages/input-core` に置き、画面は結果を表示するだけにする（既存方針）。
- 画面の権限は `capabilitiesForRole`（input-core）で決める。新しい画面は capability を追加してから作る。
- 文言は `html/*.html` のとおり。`［ ］` はプレースホルダー。

### 0.1 管理画面（PC）の骨組み

- 左メニュー：幅 232〜260px、紺地。上からロゴ、区切り見出し（小さい文字）、項目（高さ 40px、選択中は 44px・背景 `--mm-navy-active`・左に 3px の緑線・太字）、最下部にログイン中の人。
- 本文：最大幅 1240px、余白 28px 32px 48px、要素の間隔 20px。
- 画面タイトル（24px 太字・紺）＋補足行（日付・対象・「● 自動更新中（最終受信 hh:mm）」）＋右に操作ボタン。
- 狭い画面ではメニューが上に回り込む（flex-wrap）。広い表は横スクロールの箱に入れる。

### 0.2 勤務員アプリ（スマホ）の骨組み

- 上部ヘッダー：紺地。小見出し（12px・`--mm-on-navy-accent`）＋画面タイトル（22px 太字）＋右に補足。
- 下タブ：5つ固定（上番報告／シフト希望／有給申請／講習会／お知らせ）。選択中は紺・太字。お知らせに未読があれば赤い点。
- ボトムシート（確認・申込）：画面下から、上角丸 20px、背景を 55% の暗さで覆う。

### 0.3 状態と色（上番報告・申請・お知らせで共通）

| 状態 | 文字 | 背景 | 使う場所 |
| --- | --- | --- | --- |
| 出勤済み・承認済み・確認済み | `--mm-ok-text` | `--mm-ok-bg` | 配置状況、申請履歴 |
| 未確認・重要 | `--mm-alert-text` | `--mm-alert-bg`（行は `--mm-alert-soft`） | 指標、アラート、お知らせ |
| 遅刻・その他報告・休み希望 | `--mm-late-text` | `--mm-late-bg` | 指標、配置状況、シフト希望 |
| 補填済み・業務連絡・有給 | `--mm-fill-text` | `--mm-fill-bg` | 指標、お知らせ、承認一覧 |
| 欠時間・講習会 | `--mm-gap-text` | `--mm-gap-bg` | 指標、承認一覧 |
| 報告前・任意 | `--mm-neutral-text` | `--mm-neutral-bg` | 配置状況、講習会 |
| 欠勤・却下 | `--mm-absent-text` | `--mm-absent-bg` | アラート、申請履歴 |

一覧の並び順（対応が必要なものが上）：未確認 → その他の連絡あり → 出発済み → 報告前 → 上番済み → 確認済み → 本日なし（input-core `sortSlotRows` と同じ）。

### 0.4 指標（本社案の7指標）

| 指標 | 定義 | 出どころ |
| --- | --- | --- |
| 約定人数 | その日・その現場に配置する契約上の人数 | 上番データ（未実装：取込が必要） |
| 出勤確認 | 上番報告を受け付けた人数（本人＋代理） | `jyoban_reports` |
| 未確認 | 上番報告時刻＋猶予を過ぎても報告がない人数 | `computeSlotStatus` の missing |
| 遅刻 | 勤務開始後に上番、または「その他：遅刻」の連絡 | `jyoban_reports` |
| 欠勤 | 「その他：欠勤」の連絡、または責任者が確定（自動では欠勤にしない） | 新規 |
| 補填済み | 代わりの隊員を登録し、その人の上番を確認した件数 | 新規（補填記録） |
| 欠時間発生 | 配置すべき時間に誰もいなかった時間がある件数 | 新規（定義は本社確認待ち） |

## 1. 勤務員アプリ（スマホ 390×844）

### ① ログイン — `App-Login`
- URL：`/app`（未ログイン時）／既存：`apps/desktop/src/pwa/WorkerApp.tsx`
- 入力：会社コード、スタッフNo（数字キーボード）、PIN（password・数字）。主ボタン「ログイン」。
- 補足文：初回PINは生年月日から作られている／初回ログインで変更／忘れたら現場責任者に初期化を依頼。
- 最下部：ログインするとこのスマホが上番報告用の本人端末として登録される（既存 `ensureLoginDevice`）。

### ② 上番報告タブ（現場を選ぶ）— `App-Sites`
- 既存：`apps/desktop/src/pwa/jyoban/JyobanTab.tsx`
- 登録済み現場のカード（最大10件）。**本日勤務がある現場を一番上**に出し、紺の太枠＋「本日の勤務」バッジ＋勤務枠と出発済み時刻を表示（並べ替えは新規）。
- その他の現場は細枠、「本日の勤務なし ｜ 次回 m/d（曜）勤務枠」。
- 点線枠ボタン「現場を登録（QRを読み取る）」→ 既存 `QrScanner`。
- カードを押すと ③。

### ③ 報告 — `App-Report`（確認シートは `App-Report_確認シート.png`）
- 既存：`apps/desktop/src/pwa/jyoban/JyobanApp.tsx`
- ヘッダー：「← 現場一覧」、現場名、日付と勤務枠、オンライン状態。
- 進み具合の3マス：出発（済なら緑・時刻）／上番（次にやるもの＝紺の太枠・期限）／下番（勤務終了以降）。
- 大きい主ボタン（高さ約210px・紺・角丸20px）：次にやる報告（上番（出勤））＋「期限 hh:mm ｜ 現在 hh:mm」。
- 下番（退勤）ボタン：上番前は無効表示「上番後に押せます」。**下番報告は新規**（DBの報告種別追加が必要）。
- 「その他（遅刻・寝坊・欠勤など）」：橙の枠ボタン → 既存のその他報告。
- 主ボタンを押す → ボトムシート「上番を報告しますか？」＋「はい、報告する」（`--mm-green-text` 背景）／「いいえ」。
- 最下部：「電波がない場所でも押せます。つながった時点で自動で送信します。」（既存の送信待ち）。

### ④ 受付完了 — `App-Done`
- 緑の丸チェック、「上番を受け付けました」、受付時刻（64px）、日付。
- 明細カード：報告者（氏名・No・本人/代理）、勤務枠、期限（期限内なら緑）。
- 「閉じる」（③へ）、「間違えたので取り消す（12時間以内）」（既存 `voidReport`）。

### ⑤ 代理報告（現場責任者）— `App-Proxy` 【新規】
- ヘッダー：「代理報告 ｜ 現場責任者：氏名」、現場名、未報告人数。
- 1. 対象者を選ぶ：未報告者の一覧（ラジオ型の大きいボタン）。協力会社の人も含む。
- 2. 報告の種類：上番／下番／欠勤（3つの切替）。
- 3. 理由（任意）。
- 主ボタン：「〇〇さんの上番を代理で報告」（選択に応じて文言が変わる）。
- 記録：代理した人を報告に残す（`jyoban_reports` に代理者の列を追加）。

### ⑥ シフト希望 — `App-Shift`
- 既存：`apps/desktop/src/pwa/screens/ShiftHope.tsx`（勤務可／夜勤希望／休み希望をタップで登録して提出）
- 月の切替（‹ ›）、凡例（可・夜・休）、7列のカレンダー（日曜赤・土曜青、1マス高さ52px）。
- タップで「未入力 → 可 → 夜 → 休 → 未入力」と切り替わる。可＝緑地、夜＝紺地白文字、休＝橙地。
- 集計行：勤務可・夜勤・休み・未入力の日数。備考欄。主ボタン「この内容で提出する」。
- ヘッダー右：提出期限（現場が設定。期限の設定は新規）。

### ⑦ 有給申請 — `App-Leave`
- 既存：`apps/desktop/src/pwa/screens/LeaveApply.tsx`
- ヘッダー右：残り日数。
- 申請カード：開始日・終了日（2列）、「n日間の申請（残り x日 → y日）」、理由（先頭に固定文字「私用の為、」＋入力）、「申請する」、承認の流れの説明。
- 申請履歴：承認待ちは3段の進み具合（申請 → 現場承認 → 本社承認、済みは緑・未は点線）。承認済み・却下はバッジ、却下は理由を橙文字で表示。

### ⑧ 講習会・研修 — `App-Training`（申込シートは `App-Training_申込シート.png`）
- 既存：`apps/desktop/src/pwa/screens/TrainingApplyPwa.tsx`
- 今年度の現任教育：受講時間／10時間のバーと残り時間の案内（**時間の集計は新規**。法定：年度10時間）。
- 開催予定カード：区分バッジ（現任教育（法定）＝紺／任意＝灰）、残席／定員、名称、日時・会場、「申し込む」。
- 申込シート：氏名・生年月日・部署を自動表示（既存の自動適用）、「この内容で申し込む」「やめる」。
- 申込後：カード内に3段（申込済 → 現場承認 → 会社受理）。

### ⑨ お知らせ — `App-Notice`
- 既存：`apps/desktop/src/pwa/screens/Notices.tsx`
- ヘッダー右：未確認件数。
- 一覧カード：未読の赤い点、区分バッジ（重要＝赤地白文字／業務連絡＝青／お知らせ＝灰）、発信元と日時、件名。未読の重要は赤い太枠。
- カードを押すと本文を開閉。「確認しました」で既読（既読は本社・現場に集計される。DB化は未実装）。

## 2. 管理画面（PC 1440幅・可変）

### 本部｜全社 配備状況サマリー — `Main` 【新規】
- 入口：`/co`（会社ロール）。左メニュー：配置確認（全社の状況・支店別の状況・現場一覧・アラート一覧（件数バッジ）・上番報告の設定・QR）、業務（勤務員・名簿／有給の確認／講習会・教育／労務ルール／お知らせ配信／CSV・帳票出力）。
- 指標8枚（登録現場数＋§0.4の7指標）。未確認は赤の太枠、0件のときは通常枠に戻す。
- 支店別の表：支店・現場数・7指標・状態（要対応／正常）。最終行に合計。行を押すと支店画面へ。
- 対応が必要な現場：未確認・欠勤・欠時間の一覧（種類バッジ・現場と勤務枠・詳細・支店）。「対応済みにする」で記録（既存 `jyoban_acks`）。
- 自動更新：Supabase Realtime で `jyoban_reports` の変更を受けて再集計。

### 支店｜本日の状況 — `Branch` 【新規】
- 入口：`/co`（新しい支店ロール。見える範囲は配下の現場だけ）。
- 指標8枚、区分の切替（すべて／施設／交通／協力会社）、現場別の表（No・現場・区分・7指標・状態の点と文字）。行を押すと施設画面へ。
- 補填の手配：欠勤者・代わりの隊員・上番予定・欠時間の帯、「代わりの隊員を変更」「＋ 補填を登録」。
- 必要なDB：現場の所属支店、勤務員の区分、補填記録（すべて新規）。

### 施設責任者｜本日の配置状況 — `Facility` 【新規】
- 入口：`/s`（現場ロール）。
- 指標4枚（約定人数・出勤確認・未確認・遅刻）。
- 勤務者ごとの表：No・氏名とスタッフNo・区分・勤務枠・出発・上番・下番・状況バッジと備考・操作。
- 操作：未確認の人に「代理で上番」（押すと出勤済み（代理）に変わる）と「電話」、遅刻の人に「電話」。
- 注記：代理した人が記録されること、協力会社の人はこの画面から代理で報告すること。

### 現場コンソール｜ホーム — `Site-Home`
- 既存：`apps/desktop/src/features/dashboard`
- 左メニューは全モジュールを4分類（配置・勤怠／日報・記録／人・教育）で表示。
- 「今日やること」：最上段に配置状況の赤い帯（未確認・遅刻の要約、出勤確認／約定人数、「配置状況を開く」）。
- カード6枚：日報（未入力）、申請の承認（件数）、シフト希望（提出 n/m 人・締切）、教育・資格（期限が近い人数）、労務アラート、お知らせ（未確認）。各カードから該当画面へ。

### 現場コンソール｜申請の承認 — `Site-Approvals`
- 既存：`features/leave`（一次承認）、`features/training`（一次承認）
- 種類の切替（すべて／有給／講習会／シフト希望の提出状況）。
- 表：種類バッジ・申請者（No・残日数）・内容・理由・**配置への影響**（例「11/14 約定10人中 休み希望 3人」、影響ありは橙太字。新規の計算）・操作（承認／却下）。
- 処理後は行に結果を表示（承認しました → 本社へ／却下しました）。却下は理由入力（勤務員アプリに表示）。
- 下段：シフト希望の提出状況（提出 n/m・未提出者・締切）、「未提出者にお知らせを送る」「希望を見てシフトを作る」。

### 本社｜お知らせ配信と既読 — `HQ-Notice`
- 既存：`features/notify`
- 左：新しいお知らせ。宛先（全社／支店／現場／個人）と届く人数、区分（重要・業務連絡・お知らせ）、件名、本文、「確認しました」を求めるチェック、「配信する」「下書き保存」。
- 右：配信済み一覧。区分・宛先・日時・件名、確認済み人数のバー（確認 n / m）、未確認者と「再通知する」。
