# 勤務員アプリの生体認証（顔・指紋）

勤務員アプリに、顔・指紋（WebAuthn パスキー）を使った次の2つを入れています。

1. **ログイン**: PINの代わりに顔・指紋でログインする。PINはそのまま予備として使える。
2. **上番報告の本人確認**: 起床・出発・上番・下番・遅刻などを送る直前に、顔・指紋で本人か確かめる（代理報告の防止）。

## 何を保存するか

- 顔・指紋のデータはスマホの中で照合され、アプリにもサーバーにも届きません。
- サーバーに保存するのは、パスキーの**公開鍵**と認証回数、登録した端末の情報だけです（`staff_passkeys`）。
- 報告には「本人確認済みか」（`jyoban_reports.bio_verified`）が記録されます。

## 仕組み

```
勤務員アプリ ──(端末シークレット＋署名)──▶ APIゲートウェイ /api/passkey ──(service_role の RPC)──▶ Supabase
                                                   └ 署名を検証（@simplewebauthn/server）
```

- 顔・指紋を登録できるのは、スタッフNo＋PINで本人登録した端末だけです（端末シークレットで勤務員を特定）。
- 本人確認に成功すると、その端末に確認時刻が記録されます。**5分以内**にその端末から送った報告に `bio_verified=true` が付きます。
- 現場の設定が「必須」のときは、確認していない報告をデータベースが受け付けません（アプリを経由しない直接の送信も拒否）。
- 共用端末（現場スマホでスタッフNo＋PIN）からの報告は対象外で、「本人確認なし」として記録されます。
- 電波がなく送信待ちになった報告は、つながったあと「顔・指紋で確認して送信」で送れます（必須の現場）。

## 現場ごとの設定

会社コンソール → 上番報告の設定 → 現場 → 端末 → 「顔・指紋の本人確認」

| 設定 | 動き |
|---|---|
| 使わない | これまでどおり（既定） |
| 使える人は使う | 登録した人は報告のときに顔・指紋で確認。確認できなくても報告は届き、「本人確認なし」と記録 |
| 必須 | 確認しないと報告を送れない。顔・指紋が使えないスマホの人は本社に相談 |

1名配置や、代理報告が問題になった現場から「必須」にするのがおすすめです。

## 導入の手順

1. マイグレーション `supabase/migrations/0410_biometric_passkey.sql` を適用する。
2. APIゲートウェイ（`server/`）に環境変数を設定する（`server/.env.example` 参照）。
   - `WEBAUTHN_RP_ID`: 勤務員アプリのドメイン（例 `mamorai.tryangrow.com`）
   - `WEBAUTHN_ORIGINS`: 勤務員アプリのオリジン（例 `https://mamorai.tryangrow.com`）
   - `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY`
   - `CORS_ORIGIN`: 勤務員アプリのオリジン
   - `TRUST_PROXY`: 前段にプロキシがあるとき `1`
3. 勤務員アプリ（`apps/desktop`）の `VITE_API_BASE` を APIゲートウェイのURLにする。未設定なら顔・指紋の案内は出ません。
4. 会社コンソールで、試す現場だけ「使える人は使う」にする。

**注意**: 独自ドメインへ移ると `WEBAUTHN_RP_ID` が変わり、登録済みの顔・指紋は使えなくなります（PINでログインして登録し直し）。

## 困ったとき

- **スマホを替えた・紛失した**: 新しいスマホでPINログインし、登録し直す。古いスマホの鍵は会社が失効できる（RPC `company_revoke_staff_passkeys`）。
- **顔・指紋が通らない**: PINでログインできる。必須の現場で報告できないときは本社へ電話。

## 検証

- DB: `PGPORT=5439 bash supabase/tests/run_jyoban_rls_check.sh`（`biometric_check.sql` の20項目）
- サーバー: `pnpm --filter @mamorai/server exec vitest run src/passkey`（ソフトウェア認証器で実際に署名・検証する11項目）
