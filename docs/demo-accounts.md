# デモ用アカウント

社内説明・会議・新しい開発メンバー向けに、実在の人や現場を含まないデモ会社を用意する手順です。
ログイン情報（パスワード・PIN）はこのリポジトリに書きません。

## 作られるもの

| 系統 | ログイン方法 | デモで使うアカウント |
|---|---|---|
| 会社 `/co` | メール＋パスワード | 会社管理者 `demo-admin@example.com`、権限者 `demo-manager@example.com` |
| 現場 `/s` | 会社コード＋施設コード＋現場PIN | `DEMO-SC01` デモ商業施設 中央館、`DEMO-OF02` デモオフィスタワー（1名配置）、`DEMO-EV03` デモイベント会場 |
| 勤務員アプリ `/app` | 会社コード＋スタッフNo＋PIN | スタッフNo `9001`〜`9006`（名前に「デモ」が付く架空の6名） |

会社コードは `DEMO-0001`（デモ警備株式会社）です。あわせて次の例も入ります。

- 勤務枠4件（出発連絡の要否が現場ごとに違う例、1名配置の例）
- 今日の上番報告の例（報告あり・遅刻連絡）
- 12月の現任・新任教育の日程5件と受講申込2件
- お知らせ2件、有給申請1件

SMS・自動音声電話・メールの通知はオフで、勤務員の電話番号も登録しません。

## 作り方

1. 検証用（ステージング）の Supabase プロジェクトを開く。本番で行う場合も、触るのはデモ会社のデータだけです。
2. Authentication → Users → Add user → Create new user で、上の2つのメールのユーザーを作る（Auto Confirm User にチェック）。パスワードは強いものにして、パスワード管理ツールで共有する。
3. SQL Editor で `supabase/helpers/seed_demo.sql` を実行する。
4. 最後に表示される一覧（現場PIN・勤務員PIN）を控える。PINは実行のたびに新しくなる。

もう一度実行すると、PINだけが新しくなります（デモのあとにPINを変えたいときに使う）。

## 片付け

SQL Editor で `supabase/helpers/reset_demo.sql` を実行すると、デモ会社のデータだけが消えます。
会社コードが `DEMO-` で始まらない会社は消えません。Auth のユーザーは Authentication → Users で削除してください。

## デモで見せる流れの例

1. 勤務員アプリで `9004`（1名配置の現場責任者）としてログインし、出発連絡を送る。
2. 会社 `/co` に会社管理者でログインし、現場一覧で報告が届いたこと、`DEMO-OF02` の上番連絡がまだのことを見る。
3. 現場 `/s` に `DEMO-EV03` でログインし、遅刻連絡（電車の遅延）が入っていることを見る。
4. 会社 `/co` の教育管理で、12月の研修と受講申込を見る。
