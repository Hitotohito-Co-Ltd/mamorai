# 未報告コール（起床・出発・上番・下番）運用メモ

GUARD EXPRESS の「起床・出発・到着コール」と同じ考え方です。
報告の締切に猶予を足した時刻を過ぎても報告がなければ、自動で知らせます。

## 流れ

| 経過（締切＋猶予から） | 相手 | 手段 | 既定 |
| --- | --- | --- | --- |
| `remind_after_min` 分後 | 担当者本人 | アプリ通知・SMS | 0分 |
| `voice_after_min` 分後 | 担当者本人 | 自動音声電話（2回読み上げ） | 5分 |
| `escalate_after_min` 分後 | 管制・本社 | メール（最大10宛先） | 10分 |

通知が止まるのは、次のどれかに当てはまるときです。

- 本人がその報告をした。後の報告でもよいので、上番済みなら起床・出発の知らせは送りません。
- 本人が「その他」で遅刻や寝坊を連絡した。ただし下番には効きません。
- 本社確認済み（`jyoban_acks`）がある。この確認を付ける画面は、まだありません。
- 時間が経ちすぎた。本人への知らせは締切から60分まで、管制へのメールは180分までです。

同じ知らせは二度送りません。`jyoban_notifications` に先に記録してから送るためです。
ワーカーを二重に起動しても、重複は起きません。

## 本社の設定（上番報告設定の画面）

1. **未報告の自動通知**：手段（アプリ通知・SMS・電話）、タイミング、管制のメール宛先を設定します。保存した時点で通知が始まります。
2. **勤務枠**：起床・出発・上番・下番の「要・不要」と締切を設定します。下番の締切が勤務開始より前なら、翌日の時刻として扱います（夜勤明け）。
3. **担当者と連絡先**：勤務枠ごとに、知らせる隊員を選び、電話番号を登録します。
   - 担当者を決めていない枠は、誰も報告していなければ、管制へのメールだけが届きます。

## 隊員側

- 個人スマホで本人登録を済ませると、「お知らせを受け取る」が表示されます。
- iPhone は、ホーム画面に追加したアプリから開いた場合だけ通知が届きます。
- 共用端末（現場スマホ）には通知を登録しません。

## サーバの設定

`server/.env.example` を参照してください。
環境変数が無い手段は送信せず、台帳に `skipped` として残ります。

| 用途 | サービス | 目安費用 |
| --- | --- | --- |
| メール | Resend（無料枠 3,000通/月） | ほぼ0円 |
| SMS | Twilio | 1通 約10〜15円 |
| 電話 | Twilio Voice | 1分 約15〜20円 |
| アプリ通知 | Web Push（VAPID） | 0円 |

Twilio の注意点：

- 日本の携帯あてに SMS を送るには、送信者ID（Messaging Service）の登録と到達確認が必要です。本番の前に、実機でテストしてください。
- 電話の発信元には、Twilio で取得した番号を使います。

## 定期実行（どれか1つ）

ワーカーは1回動かすごとに判定をまとめて行います。**2〜5分おき**に起動してください。

- **A. HTTP を叩く**（Supabase pg_cron + pg_net、cron-job.org、GitHub Actions など）

  ```
  POST https://<server>/api/jobs/jyoban-calls
  Authorization: Bearer <CRON_SECRET>
  ```

- **B. コマンドを実行**（Railway Cron など）

  ```
  pnpm --filter @mamorai/server job:jyoban-calls
  ```

戻り値は件数の集計です（`candidates / planned / sent / failed / skipped / duplicate`）。
宛先や本文は返しません。
